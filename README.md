# 고양시 고령자의 대중교통 의료접근성 분석

**goyang-senior-mobility**는 고양시 고령자의 의료기관 접근성을 출발시각별로 계산하고, 저접근 지역 중 고령인구가 많이 거주하는 군집의 이동부담을 진단하는 연구 프로젝트다.

분석은 Step 1~9로 구성하고, 정책제안·교통 개선안·탄소배출 평가는 별도 작업으로 분리한다.

> **현재 상태 — 2026-10-17:** 연구 설계와 구현 구조를 정리한 단계다. 아래 코드·데이터·overrides·실행 명령은 구현할 구조와 실행 규약이다. 데이터 이전, 코드 구현, 분석 및 결과 PNG 생성은 완료되지 않았으며, 구현 진행에 따라 실행 가능 상태와 검증 결과를 갱신한다.

## 연구질문

> 고양시에서 대중교통을 이용한 의료기관 접근성이 낮은 격자는 어디에서 인접한 지역을 이루며, 이 중 고령인구가 많이 거주하는 군집은 어디인가? 해당 군집의 고령자는 의료기관까지 이동할 때 출발시각과 거주 위치에 따라 어떤 시간적·공간적 부담을 겪는가?

경기도의 추가 지역은 **파주시·양주시·의정부시·김포시**, 서울특별시의 추가 지역은 **도봉구·강북구·성북구·종로구·은평구·서대문구·마포구·강서구**다. 교통망은 이 행정경계에서 잘라내지 않고 필요한 경유·환승 구간을 포함한다.

점수의 단위는 ‘곳’이다. 임의의 0~100점 환산이나 인구와의 가중합은 하지 않는다. 군집의 **고령인구 합계는 규모**, **인구가중 접근성은 평균적인 이동조건**을 나타낸다. 시간대별 결과는 별도로 기록하며 주점수에 다시 합산하지 않는다.

08:30~17:00은 주거 대표점에서의 **출발시간 범위**다. 기본 분석에서 17:00 출발은 17:30까지의 도착을 허용한다. 지표는 의료기관 위치까지의 잠재적 이동기회이며 실제 진료·접수 가능성을 보장하지 않는다.

## 데이터 준비와 전처리 인계

기존 processed 자료를 사용할 수 있다. 다만 파일 이름만 같다고 적합한 입력으로 간주하지 않고, 아래 기준에 따라 원본 ID·필드·좌표계·기존 보정의 적합성을 확인한다.

| 자료 | 처리 요약 |
| --- | --- |
| `boundaries.gpkg` | 경계·코드·좌표계 유지. 분석에 필요한 범위 확인 |
| `elderly_population.gpkg` | 원래 인구 상태와 부모·자식 관계 유지. 빈값 0명, 숫자 0의 마스킹 처리 확인 |
| `residential_buildings.gpkg` | 도로명주소 전자지도 기반 건물·출입구·기존 확정 판정 유지 |
| `medical_institutions.csv` | 대상 지역·전문의·기관 중복 제거와 기존 좌표 보완 유지 |
| `osm_walk_network.gpkg` | 형상·거리·통행권한 유지. 기존 속도로 계산된 시간은 현재 경로계산에 사용하지 않음 |
| `gtfs.sqlite` | 시간표·원래 최소 환승시간·검증된 보완 유지. 분석망에서 제외 수단을 제거 |

보행시간은 분석 단계에서 거리와 해당 시나리오 속도로 계산한다. 기존 접속·환승 비용, 경로 캐시, 접근성 점수, 군집과 민감도 결과는 현재 분석 기준으로 다시 계산한다.

원자료부터 재생성하는 경우에도 기존 보정 판단을 다시 수작업으로 만들지 않는다. `overrides/`에 이전한 확정 판단과 근거를 적용한다. 기존 결과 화면이나 다른 채팅을 실행 중 참조하지 않아도 같은 보정이 적용되어야 한다.

자료 명세는 **`data/manifest.json`**에 저장한다. JSON의 `schema_version`과 `datasets` 목록으로 관리하고, 자료별로 `dataset_id`, 제공기관·출처 URL, 기준일, raw/processed 구분, 파일명, 프로젝트 루트 기준 상대경로, SHA-256, 좌표계, 주요 필드, 공개·재배포 조건을 기록한다. 여러 파일로 구성된 자료는 파일별 경로·해시를 기록한다. 이 명세는 대용량 데이터와 구분하여 Git으로 관리한다.

API로 좌표를 보완한 경우 요청에 사용한 주소·응답·적용 근거를 프로젝트 안에 보관한다. 동일 원자료와 저장된 응답이 있으면 API 재호출 없이 재현한다.

## 프로젝트 밖 파일을 참조하지 않는 실행

프로젝트 루트는 `run.py`가 있는 `goyang-senior-mobility/`다. 현재 터미널 위치나 특정 사용자의 바탕화면 경로로 루트를 정하지 않는다.

- 모든 연구 입력·overrides·출력·로그·캐시·임시파일은 루트 내부에서 읽고 쓴다.
- 상위 폴더나 다른 분석 폴더, 개인 홈의 패키지·캐시를 탐색하는 예외 처리를 두지 않는다.
- `..`, 절대경로, 심볼릭 링크·정션을 해석한 최종 경로가 루트 밖이면 실행 전 오류로 처리한다.
- Numba·Matplotlib·임시파일 등의 쓰기 경로를 프로젝트 내부로 지정한다. 개인 폴더에 별도 설치한 라이브러리를 `sys.path`에 추가하지 않는다.
- 한글이 포함된 전체 경로에서도 입출력이 가능한지 확인한다. OSM을 외부 영문 임시 폴더에 복사하는 방식으로 해결하지 않는다.
- 글꼴은 재배포 가능한 파일과 라이선스를 `assets/fonts/`에 둔다. 특정 Windows 글꼴 절대경로를 필수 입력으로 삼지 않는다.
- 운영체제·Python 실행환경 자체와 연구 자료 의존성을 구분한다. 패키지는 프로젝트 `.venv/`에 설치하고 버전을 기록한다.

대용량 자료를 별도로 내려받더라도 실행 전에 `data/raw/` 또는 `data/processed/`에 배치한다. 다른 폴더의 파일을 가리키는 링크만 만들어 두는 방식은 사용하지 않는다.

## 실행 순서

다음은 **코드 구현 후 제공해야 할 실행 인터페이스**다. 현재는 `run.py`와 `requirements.txt`가 없으므로 아래 명령을 실행할 수 없다. 구현 완료 시 실제 명령과 일치하는지 확인하고 이 상태 안내를 갱신한다.

`run.py`의 실행 방식은 **`raw`와 `processed` 두 가지**로 한정한다. 두 방식 모두 Step 1~9와 결과표·PNG 생성까지 수행하며, 시작 자료만 다르다.

```powershell
# 프로젝트 루트에서 환경 구성: 구현 후 사용
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 방식 1: raw 검사 → 전처리 → processed 검사 → Step 1~9 → 결과표·PNG
.\.venv\Scripts\python.exe run.py raw

# 방식 2: 기존 processed 검사 → Step 1~9 → 결과표·PNG
.\.venv\Scripts\python.exe run.py processed
```

입력·보정·경로·설정 검사는 각 방식의 시작 시 자동으로 수행한다. `data/manifest.json`을 기준으로 선택한 방식에 필요한 자료를 확인하며, processed 방식은 raw를 다시 읽거나 전처리하지 않는다. 분석에 필요한 보정·명세는 확인하되, raw 파일이 없다는 이유만으로 processed 실행을 막지 않는다. 필수 자료가 없으면 필요한 파일과 내부 배치 위치를 알려주며 외부 폴더를 자동 검색하지 않는다.

중단 후에는 같은 명령을 다시 실행한다. 프로그램이 입력·코드·설정·overrides 지문을 확인해 일치하는 완료 항목을 재사용하고 남은 계산을 이어간다. 조건이 바뀌면 영향을 받는 단계부터 새 실행으로 계산한다. 보고용 그림만 바뀌었다면 유효한 계산 결과를 사용해 출력만 갱신한다. 검사·재개·그림 출력은 내부 처리로 두며 별도 실행 명령을 만들지 않는다.

| Step | 작업 | 주요 결과 |
| --- | --- | --- |
| 1 | 인구 상태·부모/자식 관계·가중치 확정 | 250m·500m 인구 및 가중치 |
| 2 | 주거 대표점과 보행망 접속 | 대표점·접속선·상태 |
| 3 | 의료기관과 도착점 연결 | 기관별 도착점·접속 근거 |
| 4 | 보행·버스·철도·환승망 통합 | 수단 필터·시나리오별 보행비용 |
| 5 | 511개 출발시각 경로탐색 | 도달 여부·시간·경로 요약 |
| 6 | 250m 점수와 인구가중 500m 집계 | 점수 지도·매분/시간대 결과 |
| 7 | 하위 30%·Queen 군집·인구 순위 | 전체 군집 및 상위 3개 |
| 8 | 세 종류의 민감도 분석 | 비교표·필수 PNG |
| 9 | 상위 3개 군집의 취약 원인 진단 | 시간·거리·보행·대기·환승 진단 |

## overrides와 재검토

**보정 입력은 CSV로 통일한다.** 건물·통행·기관 등의 판정은 원본 ID와 변경값으로 저장하고, 위치·연결선 보정은 `overrides/geometry_overrides.csv`에 저장한다. 보정점은 X·Y 좌표, 연결선은 중간 꼭짓점까지 포함한 WKT 문자열로 기록하며 좌표계는 별도 `crs` 필드에 명시한다. 표준 보정 좌표계는 EPSG:5179다. 안내 README와 근거 사본은 보정 입력 테이블과 구분한다.

분석 시 CSV의 ID·좌표계·도형·연결 끝점을 검사한 뒤 공간자료로 변환하고, 필요한 보정용 GPKG를 `outputs/<run_id>/derived/geometry_overrides.gpkg`에 생성한다. 이 GPKG는 CSV에서 재생성하는 파생파일이며 Git에 올리거나 필수 입력으로 배포하지 않는다. 전체 건물·보행망을 overrides에 복제하지 않고 변경 대상과 필요한 보정 도형만 저장한다.

기존에 확정한 건물·출입구·보행 연결·통행권한·시간표 보정을 원본 식별자와 연결하여 이전한다. 이전 완료 뒤 같은 항목을 다시 승인받는 절차를 기본 실행에 넣지 않는다.

단, 원본 ID가 사라졌거나 근거와 새 자료가 충돌하는 경우에는 자동 적용하지 않는다. 자동 검증으로 해결할 수 없는 항목만 `review_required.csv`에 모으고, 이미 확인한 항목·단순 시간 재계산 항목은 제외한다. 영향받지 않는 계산은 계속할 수 있게 한다.

이전 군집 ID나 선정 격자 목록은 overrides에 넣지 않는다. 056번 보완 입력도 시간표 재현에 필요한 자료만 사용하고, 예전 선정 지역 목록과 분리한다.

## 결과와 민감도 PNG

결과는 `outputs/<run_id>/`에 저장한다. `run_manifest.json`에는 연구 기준, 적용 자료·보정·코드 지문, 시간표 시점, 실행 상태를 기록한다. Step별 결과는 다음 Step이 직접 읽을 수 있는 명세로 저장한다.

민감도 PNG의 필수 목록은 다음과 같다. 모두 Step 8의 `figures/`에 저장하며, 값을 담은 표도 함께 제공한다.

| 파일명 | 내용 |
| --- | --- |
| `01_time_budget_top3.png` | 고정한 상위 3개 군집의 30·40·50분 접근성 |
| `02_time_budget_profiles.png` | 시간예산별 매분 곡선과 접근 공백 |
| `03_walk_speed_top3.png` | 0.6·0.7·0.8m/s의 접근성과 접속 적격성 변화 |
| `04_cutoff_cluster_maps.png` | 하위 25·30·35%의 Queen 군집과 상위 3개 지도 |
| `05_cutoff_top3_overlap.png` | 격자·고령인구 기준 선정 지역 중첩과 군집 분리·병합 |

그림은 한글 글꼴, 단위, 범례, 기준 시나리오, 비교 범위, 실행 ID를 포함하고 저장 후 직접 열어 누락·잘림을 확인한다. 이번 문서 작성에서 실제 결과 PNG를 생성하지는 않았다.

대시보드는 확정된 점수·군집·민감도·원인 진단 결과를 읽는 조회 화면으로 구성한다. 정책 대안이나 탄소효과를 계산하는 단계를 대시보드에 숨겨 넣지 않는다.

## GitHub 제출과 대용량 자료

| 구분 | 관리 방식 |
| --- | --- |
| 코드·README·`data/manifest.json`·보정 CSV | Git으로 관리 |
| 핵심 결과표·최종 PNG | 크기와 공개 조건을 확인하여 선별 관리 |
| 대용량 raw·processed·필요한 재개용 결과 묶음 | 배포 가능한 자료만 별도 배포하고 버전·해시·내부 배치 경로 안내 |
| CSV에서 생성한 보정용 GPKG | Git 제외. 분석 시 프로젝트 내부에서 생성 |
| 계산 캐시·임시파일·개인 가상환경·중복 백업 | Git 제외, 재생성 가능하도록 구현 |
| API 키·개인 인증정보 | Git 제외. 기본 재현은 저장된 응답을 우선 사용 |

단계 간 결과를 Git에 전부 올릴 필요는 없다. 실행하면 생성되는 파일은 입력·출력 명세와 재생성 코드를 제공한다. 경로탐색처럼 계산비용이 큰 결과만 선택적으로 배포하고, 그것이 어떤 입력·설정에서 생성되었는지 함께 기록한다. 별도 배포 위치는 실제 업로드 후 자료 명세에 기입하며 존재하지 않는 다운로드 링크를 만들지 않는다.

## 해석 범위

본 연구는 시간표와 보행모형에 따른 잠재적 접근성을 다룬다. 실제 교통 지연, 개별 고령자의 신체 차이, 진료 예약·접수 마감, 의료의 질과 수용능력을 모두 반영한 결과는 아니다. 하위 30%는 고양시 내부의 상대적 분류이며, 군집 고령인구 순위는 규모를 기준으로 한 분석 우선순위다. 자료 부족으로 계산하지 못한 값과 실제 도달 가능한 기관이 없는 0점은 구분한다.
