# 구산·법곳·가좌 똑버스 의료이동 대시보드

`goyang-senior-mobility` 저장소의 `dashboard/`에서 관리하는 대시보드입니다. 카카오맵과 현재 선택 조건을 설명하는 AI 문답을 제공합니다. 기본 AI 제공자는 **Gemini**, 기본 모델은 **gemini-3.1-flash-lite**입니다. AI 키를 등록하기 전에는 ‘연결 준비 중’을 표시하며 지도와 계산은 독립적으로 작동합니다.

## 준비된 기능

- 대상: 본 분석 저접근 2위 군집(C002) 구산·법곳·가좌 일대 784명·39격자·118개 출발점.
- 결과 카드 3개: 30분 안에 병원 도달 비율(버스 또는 똑버스), 연간 운영비 추정, 연간 탄소 감축량.
- 조건: 똑버스 미도입/기존 정류장에 도입/가상 정류장 21곳 추가/36곳 추가, 주변 내과·정형외과 직행/일산백병원 직행/대화역 하차 후 일산백병원 이동, 차량 1~3대, 전기·LPG·하이브리드, 전환율, 재차인원.
- 기본 전기차: 스타리아 일렉트릭 11인승. 탄소 범위는 배기관 CO₂로 고정하며 전력 발전·제조 배출은 제외합니다.
- 집 출발부터 30분 도달을 평가합니다. 집에서 호출 후 기다렸다가 정류장에 차량 도착 1.5분 전에 도착합니다. 집 안 대기는 별도 표시합니다.
- Gemini 색상과 명칭을 표시하고, 질문 직후 생각 중·경과시간·응답 작성 상태를 보여줍니다. 완료·오류·중지 시 진행 표시를 정리합니다.
- 지도 격자의 색과 상세값도 선택 조건별 30분 도달 개선을 반영.
- 질문 당시 선택 조건을 서버에서 검증하고 같은 `dist/model.js`로 다시 계산.
- 조건 비교 질문에는 `calculate_scenario` 함수 호출. 비교 카드는 실제 함수의 반환값을 표시하며 화면 조건을 자동 변경하지 않음.
- 답변 스트리밍, 중지, 대화 지우기, 추천 질문, 근거 페이지의 [S1]~[S8] 출처 링크.
- API 키는 서버 환경변수로만 사용. 공개 `/config.js`에는 지도용 JavaScript 키만 전달.
- 세션별 대화 분리, 입력 1,200자 제한, 기본 세션당 10분 8회 / 서버 전체 UTC 하루 100문답 / 동시 2문답 제한.
- Render용 `PORT`, `0.0.0.0`, `/healthz`, `render.yaml`, 패키지 잠금 파일.

외부 AI 응답 품질과 계정별 이용 가능 여부는 실제 키 등록 후 확인해야 합니다. 현재 검증은 모의 API 응답을 이용한 연결·계산·오류 처리 검증입니다.

미도입은 기존 대중교통·보행의 기준선을 별도로 계산합니다. 똑버스 추가 운영비와 감축량은 0, 전환 배출량 비교는 해당 없음이며 자동차 경로 조회 없이 표시합니다. 도입 관련 조작은 비활성화하고 다시 도입안을 선택하면 보관한 조건을 적용합니다. 화면과 AI 계산은 `none/t0/t21/t36` 네 안만 지원합니다.

## 로컬 실행

Node.js 22.16 이상(권장 24)이 필요합니다. Python, GIS 프로그램, Streamlit, 별도 데이터베이스 설치는 필요하지 않습니다.

Windows PowerShell에서 저장소 루트의 `dashboard` 폴더로 이동한 뒤 실행합니다.

```powershell
cd dashboard
.\start-local.ps1
```

기존 환경변수에 없는 키만 화면에 보이지 않게 입력받습니다. 키를 파일에 저장하지 않습니다. Gemini 키 입력을 건너뛰면 지도·계산과 문답창의 연결 대기 상태를 확인할 수 있습니다. 실행 후 `http://localhost:8080`으로 접속합니다. 카카오 앱의 JavaScript SDK 도메인에도 이 주소를 등록해야 합니다.

이미 환경변수를 등록했다면 모든 OS에서 다음으로 실행할 수 있습니다.

```text
npm ci --omit=dev
npm start
```

`npm start`는 `dashboard/.env`가 있으면 읽을 수 있지만 실제 키 파일은 배포 소스에 포함하지 않습니다. 실행창을 닫으면 로컬 서버는 종료됩니다.

## Gemini 키 등록

1. [Google AI Studio API Keys](https://aistudio.google.com/apikey)에서 프로젝트를 선택하고 키를 발급합니다.
2. 로컬은 실행창의 키 입력 또는 환경변수 `GEMINI_API_KEY`를 사용합니다.
3. Render는 서비스의 **Environment → Add Environment Variable**에서 `GEMINI_API_KEY`를 등록하고 재배포합니다.
4. `AI_PROVIDER=gemini`, `GEMINI_MODEL=gemini-3.1-flash-lite`를 확인합니다.

기본 모델은 공식 문서에 공개된 stable 모델입니다. 계정의 모델 접근·무료 쿼터는 별도 확인해야 합니다. 화면이 ‘연결됨’이어도 실제 API 인증·과금·한도는 첫 문답으로 확인됩니다. 무료 한도 초과 시 자동으로 다른 공급자로 넘어가거나 유료 결제를 생성하지 않습니다.

OpenAI를 사용하려면 `AI_PROVIDER=openai`, `OPENAI_API_KEY`, `OPENAI_MODEL=gpt-6-luna`로 바꿉니다. 두 제공자의 키는 서로 대체하지 않습니다.

## Render에 배포

배포 저장소는 **ParkJH0313/goyang-senior-mobility**, 실행 기준 폴더는 **dashboard**입니다. Blueprint 설정은 저장소 루트의 [`render.yaml`](../render.yaml)에 있습니다.

1. Render 서비스의 연결 저장소를 `ParkJH0313/goyang-senior-mobility`, 브랜치를 `main`, Root Directory를 `dashboard`로 설정합니다.
2. 기존 서비스는 아래 빌드·시작 명령을 유지합니다. Blueprint로 구성할 경우 저장소 루트의 `render.yaml`을 사용하며, 기존 서비스와 같은 이름과 무료 플랜을 지정합니다.
3. 생성 과정에서 `KAKAO_JAVASCRIPT_KEY`, `KAKAO_REST_API_KEY`를 입력합니다. Gemini 키는 발급 후 Environment에서 추가해도 됩니다.
4. 생성된 `https://서비스이름.onrender.com` 주소를 카카오 앱의 **JavaScript SDK 도메인**에 등록합니다.
5. `/healthz`가 `{"status":"ok"}`를 반환하는지 확인하고 실제 대시보드를 엽니다. 서비스 주소는 Render의 `RENDER_EXTERNAL_URL`에서 자동으로 읽습니다. 자체 도메인을 쓰면 `APP_ORIGIN=https://본인도메인`을 추가합니다(마지막 `/` 제외).
6. AI 키 등록 후 ‘왜 이 지역인가요?’, ‘미도입과 세 도입안을 비교하면?’, ‘운영비·감축량의 범위는?’을 질문해 답변과 화면의 계산값을 비교합니다.

Blueprint 대신 **New → Web Service**로 만들 때는 아래 값을 사용합니다.

| 항목 | 값 |
|---|---|
| Runtime | Node |
| Root Directory | `dashboard` |
| Build Command | `npm ci --omit=dev` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |
| 환경변수 | `../render.yaml`의 목록 참고. 실제 배포에서는 `HOST=0.0.0.0`, `PORT`는 Render 제공값 |

웹사이트 주소를 공유하면 방문자는 설치나 API 키 입력 없이 이용합니다. API 호출 비용은 배포자의 계정에 발생합니다. 현재 구성은 단일 서버용이며 대화·횟수 제한·거리 캐시는 서버 재시작 때 초기화됩니다. 따라서 앱의 횟수 제한은 월 결제금액의 강제 상한이 아닙니다. 대규모 공개 운영에는 공유 저장소 기반 제한이 추가로 필요합니다.

## 자료·계산 범위

`dist/data.json`은 본 분석 결과로 만든 schema 6 고정 자료입니다. 784명, 500m 39격자, 250m 출발점 118개, 건물 수요점 737개를 포함합니다. 모든 수요점에 배치별 도보 10분 이내 전체 승하차 후보 ID와 보행시간을 저장하고 10분 초과 수요는 이용권에서 제외합니다. 21곳을 유지한 채 36곳, 36곳을 유지한 채 61곳으로 늘리는 누적 배치 자료입니다. 화면에서는 미도입·기존 정류장 도입·21곳·36곳을 비교하며, 61곳 자료는 분석 재현과 누적 기회 보존 검증을 위해 보관합니다.

기준은 **0.8m/s**입니다. 기존 정류장 공급을 유지한 5분(240m) 인구 피복 최대화 MCLP를 SciPy MILP로 풉니다. 도로 후보 741개를 같은 5분 피복 조합별 248개로 정리했습니다. 이번 누적 배치의 최적성 간격은 모두 0이며, 36·61곳은 앞 단계 지점을 유지하는 조건 아래의 최적해입니다.

이전 배포 경로에서 기존 정류장만 43.18%, 21곳 추가 42.72%로 도달률이 하락하는 현상을 재현했습니다. 보행상 가장 가까운 한 정류장으로 강제 재배정하며 차량 이동이 긴 경로를 고른 것이 원인이었습니다. 이제 기존 후보를 유지하고 보행·정류장 대기·차량·후속 이동의 합이 빠른 후보를 출발시각별로 고릅니다. 고정 배차·우회 조건에서 정류장 추가가 기존 기회를 없애지 않음을 모든 격자에서 검사합니다. 실제 수요 증가가 대기를 늘리는 영향은 포함하지 않았습니다.

| 추가 정류장 | 도보 5분 내 | 도보 10분 내 |
|---|---:|---:|
| 0 | 24.52% | 66.73% |
| 21 | 70.14% | 85.90% |
| 36 | 80.48% | 92.48% |
| 61 | 90.10% | 94.73% |

본 분석을 다시 실행해도 대시보드 자료는 자동 갱신되지 않습니다. 다시 만들 때 저장소 루트에서 실행합니다. GIS Python 환경, 본 분석 `outputs/`, `data/processed/`, 로컬 경로 캐시(`.cache/analysis`)가 필요합니다. 서버 실행 자체에는 Python이 필요하지 않습니다.

```powershell
.\.venv\Scripts\python.exe dashboard\analysis\build_data.py
```

생성 스크립트는 본 분석 파일을 읽기만 하고 `dist/data.json`을 교체합니다. 실행 ID·생성시각·주요 입력과 생성 코드 해시를 저장합니다. 이번 기준 실행은 `v7_213b657093b3`입니다. 재생성 후 `dist/about.html`의 표·생성시각 및 `knowledge.cjs`의 근거 내용도 맞춰야 합니다.

`routing.cjs`는 주변 의료기관 직행에서 이전 버전과 같은 출발지별 원내과의원·일산중심재활병원 배정을 복구합니다. 각 출발지→배정 의료기관의 자동차 왕복 기준선과 실제 승차 지점→해당 기관의 왕복을 조회합니다. 백병원 직행·대화역 경유는 모두 주거 대표점→일산백병원 자동차 왕복 기준선과 실제 승차 지점→백병원/대화역의 왕복 경로를 조회합니다. 백병원 직행에는 하차 보행 1분, 대화역 경유에는 하차 준비 1분과 실제 정류장 출발의 도보·시간표 후속 경로를 적용합니다. 후속 출발시각은 17:30까지 확장하며 GTX는 제외합니다. 지도는 녹색 하차 지점과 황토색 최종 병원 역할을 구분합니다.

주변 의료기관 직행은 이전 Step9 기준선 14.5844%를 사용합니다(`origins.bus`, `access.baselineShare`). 여러 대상 내과·정형외과 중 1곳 이상에 도달하는 기존 대중교통과 출발지별 최근접 기관으로 가는 똑버스를 합쳐 평가합니다. 백병원 두 안은 Step5 OD 행렬의 백병원 열에서 추출한 1.4238%를 사용합니다(`origins.busBaek`, `access.baekBaselineShare`). 미도입에서도 목적지 선택을 유지하며 화면·지도·AI의 기준선을 함께 전환합니다. 두 범위의 수치 차이는 동일 병원에 대한 순수한 정책 효과가 아닙니다.

대화역·일산서구청 비교는 `analysis/compare_hubs.cjs`와 `analysis/hub_comparison.json`에 기록했습니다. 공개 배포본과 동일 실행의 경로 스냅샷을 사용했고 현재 생성 자료와 승차 후보·좌표·후속 시간표가 같은지 확인했습니다. 두 경로 모두 계산 가능한 동일 인구·시각을 기준으로, 36곳 추가 시 총 이동 평균은 대화역 32.88분 / 서구청 35.46분입니다. 기존 정류장·21곳 안에서도 대화역이 더 짧았습니다. 이 두 후보 중 선택이며 전체 최적 거점은 아닙니다. 서구청 후속 프로필은 비교 재현용으로 데이터에 남기지만 화면·API·AI 선택지는 `clinic/baek/daehwa`를 지원합니다. 원본 경로 응답은 `.tmp/dashboard-review/selection-{daehwa,seogu}.json`, 당시 데이터는 `.tmp/dashboard-review/current-live-data.json`에 로컬 보관했고 보고서에 SHA-256을 기록했습니다. 재계산은 `node dashboard/analysis/compare_hubs.cjs <data.json> <daehwa.json> <seogu.json>`로 수행합니다.

경로는 서버 메모리에만 저장합니다. 목적지 첫 조회에서 주거점과 모든 배치의 승하차 지점들을 기관별로 묶어 최대 30개씩 왕복 요청하므로 종전의 주거점만 조회할 때보다 요청 수가 늘어납니다. 같은 OD는 재사용하고, 정류장·차량·슬라이더 변경에는 추가 요청하지 않습니다. 실패 후 1분 동안 재시도를 늦춥니다. 경로 누락 때는 탄소·도달 결과를 숨깁니다.

`dist/model.js`를 브라우저와 AI 서버가 공유합니다. 호출 후 예상 차량 도착 W, 보행 L, 정류장 대기 B=1.5분에 대해 확정 탑승시각은 `P=max(W,L+B)`, 집 안 대기는 `P-L-B`입니다. 집 출발부터의 이동에는 `L+B+차량+후속이동`을 넣습니다. 집에서 대기한 시간을 30분 지표에 넣지 않으므로 이전 호출 기준 수치와 직접 비교해 개선량으로 해석하지 않습니다.

차량 도착 민감도는 `14.5 × √(2/차량 수)`분: 1대 20.51분 / 2대 14.50분 / 3대 11.84분입니다. 화면의 기준 대기는 14.5분으로 고정하고 차량 대수 아래에 계산된 호출~탑승 시간을 표시합니다. 대기 슬라이더는 제거했으며, 보고서 관측값과 2대 적용 가정을 출발 준비 설명에서 구분합니다. AI 비교 도구는 별도 기준 대기시간의 민감도 비교를 지원합니다. 차량 도착을 예측하고 출발 시점을 맞추는 가정이므로 차량 수만 바꾸면 집 안 대기와 예산이 달라지고 집 밖 이동시간은 같을 수 있습니다.

차종별 예산은 LPG 사례원가 560,428원/대·일에서 가정한 에너지·정비·감가상각을 빼 공통비를 구하고 각 차종 비용으로 교체합니다. 하루 200km, 8년 감가상각, 잔존가치 0, 365일을 가정합니다. 전기/LPG/하이브리드 단가는 300원/kWh·1,200원/L·1,750원/L, 정비비는 50·80·70원/km입니다. 현재 시장가격을 의미하지 않습니다. 차량 구입가 합계는 별도 참고이며 연간 원가에 다시 더하지 않습니다. 수식과 차량 제원 출처는 `dist/about.html#budget`, `#vehicles`에 있습니다.

## 해석의 한계

- 대기식은 배차 시뮬레이션이나 관측 회귀식이 아닙니다. 제공 보고서의 14.5분은 광교 10대 운영 중 배차 성공자의 평균이며 이 지역 2대로 옮긴 것은 별도 가정입니다. 호출 거부·취소·차량 정원·일반 수요·충전 중 가동률을 검증하지 못했습니다.
- MCLP는 5분 보행권 인구만 최적화합니다. 10분권, 전체 이동시간, 탄소 최적성은 보장하지 않습니다. 도로폭·정차 안전·회차·휠체어 접근과 건물 출입구는 현장 검증이 필요합니다.
- 탄소는 **택시·자가용에서 전환한 의료 왕복통행에 배분된 효과**입니다. 전체 차량의 하루 운행거리·일반 승객·차고지 이동이 없어 사업 전체 순감축은 아닙니다. 현재 예약 탑승 가정에서 차량 수만 바꾸면 집 안 대기·운영비가 바뀌고 집 출발 기준 접근성은 같으며, 고정 수요·재차인원에 배분한 탄소량은 그대로일 수 있습니다.
- 배기관 CO₂만 평가하므로 전기차 0과 해당 전환통행 100% 감소가 표시됩니다. 전력 발전·연료 생산·배터리 제조를 포함한 전 과정 감축이 아닙니다. 전기 스타리아는 실제 전기저상 똑버스 제원을 대표하지 않습니다.
- 환승 후 기존 대중교통은 추가 운행 0을 가정합니다. 추가 증편이나 승객별 배분 배출을 포함하지 않으며, 귀가편 환승·보행도 따로 검증하지 않습니다. 최근접 의료기관 선택은 OSM 무방향 도로망 근사이고 최종 거리는 카카오에서 조회합니다.
- 23.7회 외래 빈도·외출 주수단 비율은 의료통행 대리자료입니다. 실제 의료 수요·탑승률과 다를 수 있습니다. 잠재 도달률은 인구·출발시각 가중 비율이며 실제 이용률은 아닙니다.
- 차종별 운영원가는 가정으로 분해한 비교값이며 실제 견적이 아닙니다. 충전시설·금융비·보조금·운임수입·차종별 보험료 차이는 제외합니다.

수식과 출처는 `dist/about.html`, AI 설명 근거는 `knowledge.cjs`에 함께 반영했습니다.

## 검증

```text
npm test
npm run check
npm run test:ui
```

서버·계산 테스트는 외부 API 없이 Gemini/OpenAI 도구 호출, 서버/브라우저 계산 일치, 정류장 배정과 인구 보존, 정류장 추가 시 기회 보존, 예약 탑승 시각, 차종별 원가, 배기관 범위, 17시 이후 거점 연결, 실제 승하차 좌표 사용, 오류 처리를 검사합니다. MCLP는 별도로 완전열거 최적해와 비교하는 반례 테스트를 실행합니다.

```powershell
# 저장소 루트
.\.venv\Scripts\python.exe -m unittest discover -s dashboard/analysis -p 'test_*.py'
```

브라우저 검증에는 Playwright와 Chrome이 필요합니다. `PLAYWRIGHT_MODULE`, `CHROME_PATH`로 경로를 지정할 수 있습니다. 임시 로컬 서버와 명시적인 가상 경로·AI 응답을 사용하며 운영용 모의 데이터 옵션은 없습니다. 1440px/390px 화면, 조건 변경, 오류와 재시도, 대화창을 확인하고 `artifacts/`에 이미지와 JSON을 저장합니다. 실제 카카오 지도·경로 및 AI 인증·응답 품질은 API 키를 가진 실행 환경에서 추가 확인해야 합니다.
