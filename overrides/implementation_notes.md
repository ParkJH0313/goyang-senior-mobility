# v7 구현 인계: 일반 기준과 보정의 경계

이 파일은 설명이며 실행 설정 파일이 아니다. 공통 수치·알고리즘은 앞으로 구현할 `run.py`, `preprocess/`, `steps/`, `src/`에 둔다. 대상별 예외만 옆의 CSV에서 읽는다. 이번 작업은 overrides 이전이며 v7 분석 실행이나 판정 적용기를 구현한 작업은 아니다.

## 적용 순서와 충돌 처리

1. 프로젝트 내부 데이터 명세와 원본 ID를 확인한다. 군부대 제외·명시적 보행불가가 연결 추가보다 우선한다.
2. 대상의 원래 속성, 좌표, 원본 way/node와 구간 형상을 expected_before/target_fingerprint 및 evidence 스냅샷과 비교한다. 지문은 정렬한 키·UTF-8·빈 공백 없는 JSON의 SHA-256이다. 원본 ID 존재만으로 적용하지 않는다.
3. 건물 분류와 통행권한을 적용한다. 이미 적용된 processed에는 같은 판정을 중복 추가하지 않는다. 원본 태그는 별도 보존한다.
4. 실제 지상 구간 위에 연결 끝점을 투영하고 분할한다. 0m 결합은 Point와 두 segment 참조로 동일 노드를 만든다. 기존 component_id나 임시 conn/node 문자열로 결합하지 않는다.
5. 출발점·의료기관·정류장 접속선과 출입구를 적용한다. 일반 접속 대신 지정 선을 사용하며 두 대안을 동시에 남겨 지름길을 만들지 않는다. 중앙정류장선과 담장 허용은 같은 정류장에서 중복 링크가 아니라 도형+허용 속성의 결합이다.
6. 양방향 연결이라도 입체교차·통행권한·철도/하천/군부대 충돌을 검사한다. 미검증 근사는 승인을 반복 요청하지 않지만 새 데이터와 충돌하면 자동 적용하지 않는다.
7. 시간표 보완을 적용하고, 모든 거리 기반 비용을 v7 시나리오 속도로 재계산한다. 출입구 고정시간 등과 구분한다. 물리 보정은 경로 계산 이전 단계에서 적용한다.
8. 적용 성공·이미 적용·충돌·대상 누락을 실행 로그에 기록한다. 자동 해결 불가이고 분석에 영향을 주는 건만 review_required.csv에 남긴다.

후보 전부의 장애물, 단순 100m 초과, 이미 승인된 가정, 단순 속도 재계산은 새 사용자 검토 이유가 아니다. 근거가 다르면 기존 승인 범위를 임의로 확대하지 않는다.

## 출발점·건물

주거 도형 면적에 따른 대표점을 유지하고 접속거리를 따로 가산한다. 주거 건물 내부·단지 주거건물 교차는 단독 차단 이유가 아니다. 주거가 없는 유인구 격자의 임시 중심점은 v7에서 지정한 상태를 유지하며 검증된 주거점처럼 표현하지 않는다. 건물면적 30/500m² 등 예전 검토 문턱은 새 건물 자동 포함/제외 기준으로 확대하지 않는다. 공관·기숙사·부속건물 및 주용도 판정의 일반 분류는 전처리 규칙이다. 6개 인구대조 건물의 포함을 유인구 격자의 모든 후보 포함으로 바꾸지 않는다.

일반 선정 기준의 자세한 기존 문구·개별 장소 대조 근거는 [전처리 판단 발췌](evidence/preprocessing_decision_excerpts.md)에 보존했다. 기본 주거 코드는 01000·01001·01002·01003·02000·02001·02002·02003·10202이며, 상세명 비주거·기숙사 제외와 개별 확정 판정의 우선순위를 함께 적용한다. 10299는 명칭 또는 개별 근거가 필요하다. 이름 없음이나 종속건물(S) 자체는 제외 이유가 아니며, 주건물의 공장·창고·학교 등 맥락과 개별 판정을 구분한다. 주거 코드와 시설명이 충돌할 때 채택했던 비주거 명칭 우선 규칙도 이 근거에 남겼다. 이 일반 규칙을 수백 개의 새로운 수작업 override로 복제하지 않는다.

## 보행권한

원본 foot와 access의 우선순위, 계단의 양방향 보행, 에스컬레이터 방향 근거, 별도 보도 이용은 전처리 규칙으로 유지한다. incline만으로 에스컬레이터 진행방향을 확정하지 않는다. 보행 근거 없는 차도·자전거전용길은 새로 보행 가능 처리하지 않는다. permit/customer/destination은 무조건 공공 통과 허용으로 바꾸지 않는다. 이번 CSV의 서비스 POI 예외는 자전거 대여시설 태그의 오해를 피하는 제한적 규칙이다.

## 철도 시간: 기존 계산식 중 하나는 v7로 대체

| 구간 | 실제 이동을 나타내는 보행시간 | 추가 처리 |
|---|---:|---|
| 출입구↔승강장 | 편도 180초 | 보행 시간과 연속보행에 포함 |
| 같은 역 일반 노선 간 환승 | 240초 | 노선 탑승 대기 별도 |
| 같은 승강장임이 확인된 환승 | 120초 | 현재 확인된 실제 적용 대상 0개; 자동 추정 금지 |
| 외부 보행이 필요한 역간 환승 | 180초 + 실제 외부 거리/속도 + 180초 | 내부 환승 240초를 다시 더하지 않음 |
| 운정 출입구↔지하 버스정류장 | 편도 180초 | GTX 탑승 없음, A↔B도 지상 경유 |
| 추가 차량 탑승 준비 | 60초 | 보행거리 환산값이 아님; 최초 탑승·동일 차량 유지에 중복 부과 금지 |

과거 코드의 `max(240, min_transfer_time - 60)`를 물리적 보행으로 저장하는 식은 **활성 override로 이전하지 않는다**. v7에서는 실제 보행, 추가 탑승 준비, GTFS 최소 경과시간을 각각 구분한다. 동일 과정을 보장하는 최소시간은 중복 합산하지 않고 경과시간 제약으로 검사한다. 해당 환승의 물리 과정에 위 시간이 어떤 방식으로 적용되는지 명시하고, 부족한 GTFS 하한을 맞추는 시간을 보행으로 변환하지 않는다. 역 내부 연결은 일반 지상 보행의 지름길로 쓰지 않는다.

## 중앙정류장·일반 담장·분리망

이름에 (중) 등 중앙정류장 표지가 있으면 인근 같은 층 횡단보도의 중간 부분을 통한 접속을 우선한다. 누락된 경우의 76개 가정은 실제 횡단보도 근거와 분리한다. 양쪽 도로가 잡힌 30개는 도로 사이 중간점을, 나머지 46개는 정류장 좌표를 중간점 대리로 쓴 기존 적용을 보존했다. 신호대기는 0이지만 횡단거리는 포함한다. 일반 담장 가정 9개와 추가 지상 분리망 연결 71개는 적용 대상을 고정해 보존했다. 새 위험 장벽 횡단을 이 정책으로 승인하지 않는다.

## 취소·대체된 과거 판단

- 대곡역 상하부 추가통로: 사용자가 취소했다. 도형을 새로 만들지 않으며 정상 역 접속 전체를 금지하지도 않는다.
- 원릉 A측 철도 횡단 대안: B 출입구 확정으로 폐기했다.
- 과거 가좌동·송포동 고정 선정과 세 대표군집 목록: v7에서는 인구 기준 상위 3개를 새로 뽑는다. 056 입력에 선정 목록을 섞지 않는다.
- 과거 보행속도·연속/총보행 한도·하위분위·Rook 군집 및 점수/캐시: 새 v7 기준을 따른다. 기존 연결선을 보존했다는 이유로 예전 비용을 재사용하지 않는다.
- 환승상한 민감도·2SFCA·범위확대 보류: 과거 실험번호 대신 v7 범위와 세 종류 민감도를 구현한다. 정책·탄소평가 결과는 이번 연구 범위에 포함하지 않는다.
- 가좌동 80분 지도 표현: 공통 범례/고정 척도로 정직하게 비교한다. 기대하는 결론에 맞춘 값 변경은 어떤 override에도 포함하지 않는다.

## 재현 범위

보정 CSV·도형·근거는 프로젝트 안에 있다. 이전 제출용 폴더는 런타임 입력이 아니다. 대상 스냅샷은 변경 검증용이며 전체 망을 대체하지 않는다. v7 데이터 배치와 적용기 구현은 별도 작업이다. 원본 API 응답의 전체 이관은 데이터 인계 시 별도로 처리해야 하며, 이번에는 35개 확정 주소 좌표를 완전 정밀도로 보존했다. raw/API를 새로 읽지 않았다는 한계를 유지한다.
