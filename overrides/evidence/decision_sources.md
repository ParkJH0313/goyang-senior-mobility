# 판단 근거와 확신 수준

이 문서는 이번 대화의 직접 발언과 기존 코드·산출물에 남은 근거를 구별한다. 작성일은 2026-10-17이며, CSV의 날짜가 있는 경우는 기존 기록에서 확인한 날짜다. 날짜를 확인하지 못한 행은 공란이다. 코드·기록이 주장하는 사용자 확인을 새로운 현장 확인으로 바꾸지 않았다.

## 직접 대화에서 확인한 판단

- 출발점: “일단 출발점은 유지하되”, 출입구를 못 찾으면 “그냥 직선으로 보행망 연결”. “주거 건물과 충돌하는건 무시해도 될거 같아”. 선택하지 않은 표시선의 장애물 교차는 필수 검토 사유에서 제외.
- 분리망: “4곳 모두 망간 최소 간격 위치로 해서 연결”. 의료기관 분리망도 “Step2처럼 망끼리 최소 간격으로 연결”. 이 지시는 개방 여부를 현장에서 확인했다는 증거가 아니다.
- 의료기관: 질문의 31개 기관에 “주소 좌표를 대리 도착점으로 쓰는 가정 허용”.
- 군부대: “보행을 할 수 없는 곳이야 분석에서 제외해야해”. 격자·건물군 ID는 당시 적용 결과에서 복원했다.
- 대곡역: 추가 통로 제안 뒤 “그냥 반영하지말고 기존에 대곡역 고려해서 했던 검토들 결과 지우고”. 따라서 새로운 통로를 저장하지 않았다.
- 철도·정류장: “철도 내부 시간은 제안대로”, “신호 대기는 우선 제외”, “고속철도·시외버스·GTX 제외”. 중앙정류장 횡단보도가 없으면 “도로에서 횡단보도 있다 생각하고 중간지점으로”.
- 원릉: “B가 출입구 맞다니까”. B의 기존 OSM 좌표를 채택하고 철도·펜스 직선 횡단 대안은 폐기했다.
- 운정: 지하차도 차도로 보행 진입 불가, 역 출입구를 이용. “A↔B 환승도 지상 경유 필요”. 후속 지도·로드뷰로 출입구 접근 보도가 도로와 같은 층임을 설명했다. 2번·1번 좌표 순서는 후속 발언으로 확인했다.
- 송추: 사용자가 ArcMap에서 근사로 찍은 좌표이며 “arcmap도 정확하지 않더라”라고 한계를 직접 설명했다.
- 056: 위치 검토안을 채택하고 processed의 기존056을 보완 자료로 교체하도록 지시했다. “일부구간은 지선 구간은 BIS에 등록되어 있지 않아서 busmaps으로 보완했다고” 기록하도록 요청했다.

## 과거 기록에서 복원한 판단

개별 건물 판정 묶음, OSM 양방향 17개·출입불가 2개·별도보도 48개는 전처리 코드의 명시적 상수와 통합기록이 사용자 판정으로 기록한다. 현재 대화에 각 ID별 원문은 모두 남아 있지 않으므로 evidence_type을 `prior_record_user_decision`으로 두었다. `source_constant_membership.csv`에 상수명·원본 ID·값을 옮겼고, 건물의 실제 최종 분류는 `building_target_snapshot.csv`로 교차 확인한다.

의료기관 지오코딩 35개는 저장된 좌표·기록의 재사용이다. 원 API 응답 40개를 이번 작업에서 재조회하거나 raw에서 열지는 않았다. 새 API 결과를 주장하지 않는다.

## 승인과 검증은 별개

`approved`는 연구 모형에 채택한 판단이라는 뜻이다. `provisional_not_field_verified`, `user_approximate_not_survey`는 승인 후에도 유지한다. 추가 정류장 분리망 71개, 추가 출발망 1개, 중앙정류장 76개 등은 승인된 규칙이 적용된 결과이지 사용자가 하나씩 현장 확인한 목록이 아니다.

CSV 속 `source_version`은 이전 시점의 산출물 스냅샷 식별자다. 원자료 기준일을 2026-10-17로 변경한다는 뜻이 아니다. 파일 지문은 `source_manifest.csv`, 대상별 속성·형상 지문은 각 판정 CSV와 target 스냅샷에 저장한다. 정확한 사용일을 확인할 수 없는 항목은 날짜 공란을 유지한다.
